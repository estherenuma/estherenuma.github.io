01 / Work

Three working systems, tested around the failures that usually break automation.

SYSTEM 01
shippedvoice

AI Voice Receptionist

conversation → live availability → booking → owner summary

Before

After-hours and overflow calls reach voicemail. Staff must qualify every caller, check the calendar, create the appointment, and copy the details into a separate record.

After

A browser-based voice receptionist qualifies the caller, checks live availability, books the selected slot, logs the call, and sends the owner a written summary.

call answeredqualifycheck calendarbooklogowner summary

Key decision

If the calendar or another connected service is unavailable, the agent does not guess. It captures a callback request so a technical failure becomes a recoverable lead rather than a false booking.

1 call
from spoken enquiry to a confirmed appointment, with the call details recorded for the owner.

SYSTEM 02
shippedlead ops

Lead Response Engine

public form → storage → ai classification → reply → owner alert

Before

Enquiries are checked manually, answered hours later, and tracked inconsistently. High-intent leads are easy to miss when the owner is busy or offline.

After

Every web enquiry is stored, classified by intent and urgency, scored for purchase readiness, answered with a tailored first response, and escalated to the owner when intent is high.

capturestore firstclassifyvalidatereplyalertupdate status

Key decision

The lead is written to storage before the model runs, and model output is validated and safely defaulted. An AI failure may delay classification; it never loses the enquiry.

< 60 sec
to deliver a useful first response in end-to-end testing while preserving the lead and its status.
n8n · google sheets · gmail · ai classification · javascript · json

SYSTEM 03
shippedsupport agent

Customer-Support AI Agent

chat → memory → knowledge tool → grounded response

Before

Support teams repeatedly answer the same policy, delivery, refund, product, and opening-hours questions, while customers wait for someone to search the approved information.

After

An AI agent remembers the conversation, calls a dedicated Airtable knowledge tool, and returns one approved answer. Unsupported questions are not answered from guesswork.

chatmemoryknowledge toolairtable searchone resultgrounded reply

Key decision

Knowledge retrieval lives in a separate tool workflow that consolidates multiple Airtable records into one structured result. That prevents duplicate agent runs and keeps the main agent simple.

1 → 1
one customer question produces one approved response instead of several Airtable items triggering duplicate answers.

03 / About

A builder first. I teach because I build, not the other way round.

approach

I build on n8n. It handles the things client work actually runs into — real branching logic, custom code where a no-code node runs out, and no per-task pricing that punishes a system for being used. I teach automation across Zapier, Make and n8n, so if a client needs to own and edit a system inside a tool they already pay for, I can build it there and I say so up front.

how I work

I start from the failure modes, not the happy path. What happens when the model returns nonsense, when the API is down, when someone submits the form twice, when the person who owns the process leaves. A system that only works on a good day is not finished. Every build is handed over with a recorded walkthrough and documentation, because a system nobody understands is a system that quietly dies.
